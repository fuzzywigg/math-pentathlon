# Hex — 3D board spec
Sources read: `src/core/game-registry.ts`, `src/games/hex/types.ts`, `src/games/hex/rules.ts`, `src/games/hex/tutorial.ts`, `src/games/hex/board-ui.ts`; official PDF `Highlights-Division-1.pdf` (page numbers left for Gemini cross-check)
Official vs engine discrepancies: None identified. The engine implementation of an 11×11 grid and connection-based win condition matches the standard rules of Hex.

Grid/topology: 11×11 rhombus of hexagonal cells, using a skewed-axial (parallelogram) coordinate system.

Coordinates shown to players: A–K for columns, 1–11 for rows (e.g., "A1", "K11"). This matches the 2D `aria-label`s generated by `buildCellAriaLabel()` with `formatPosition()`.

Players & colors: P1 Blue (connects top to bottom), P2 Red (connects left to right). The vs-AI seat uses `getPlayerSeatColors()`.

Starting position: The board is entirely empty, as created by `createInitialState()`.

Special squares: None on the grid itself. The top and bottom edges of the board are Player 1's (Blue) goal, and the left and right edges are Player 2's (Red) goal. These should be visually indicated with colored borders, matching the 2D SVG's `.hex-edge-p1` and `.hex-edge-p2` paths.

Pieces (one row each):
| Piece | Count/player | Physical form (official kit) | 3D geometry (exact) | Size (cells) |
| :--- | :--- | :--- | :--- | :--- |
| Stone | Up to 61 (one per turn on 11×11 board) | Flat chip/stone | Hexagonal prism (`ExtrudeGeometry` from a 6-sided `Shape`), short height. | 1 hex cell |

Interactions: Select empty cell → place. A click on the 3D canvas is raycast to a hex cell's `(row, col)` coordinates. This is passed to the game controller, which validates the move with `isValidMove()` and updates the state by calling `makeMove(state, {row, col})`.

Win/end condition (verbatim from engine/tutorial and mark UNVERIFIED vs official): Create an unbroken path of your pieces connecting your two edges. Player 1 (Blue) connects the top and bottom edges. Player 2 (Red) connects the left and right edges. (UNVERIFIED vs official)

Camera & framing: 3/4 perspective view from a fixed position. The camera should frame the entire 11×11 board and its colored edge indicators. The board should be oriented with Player 1's starting side (e.g., bottom edge) closer to the camera.

Out of scope: animations, a11y (Step 4), engine rule changes
