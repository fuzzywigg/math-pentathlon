# Load performance pass — 2026-10-07

Draft follow-on to the earlier menu/play-CSS split. Base:
`cursor/integration-fold-wave4-tip-36e4` (#476). Scope: first-load JS/CSS,
route/game chunk policy, idle deferral. **No** rules, scoring, AI, or copy
changes. Visual baselines untouched.

## What changed

1. **`game-shell` chunk** — `game-shell.ts` + `player-colors.ts` leave the menu
   `ui` / modulepreload graph; they load with `/game/:id` (same pattern as
   `game-routes`).
2. **`core-storage` chunk** — progress store deferred; menu `reduced-motion`
   reads a tiny `settings-flags` core helper (localStorage peek + in-memory sync
   from storage when the store loads). Debounced saves unchanged.
3. **Idle SW registration** — `bootstrapPwa()` schedules via `requestIdleCallback`
   (3s timeout) so first paint JS/CSS/font win the radio over Workbox precache.
4. **Report-only `npm run check:perf`** — writes `test-results/perf/summary.md`
   (+ JSON); always exits 0. Optional treemap:
   `PERF_VISUALIZE=1 npm run build` → `test-results/perf/stats.html`.

## Skipped (would need visual baseline updates or negligible)

- Moving more play-only rules from `style.css` / `mobile-play-shell.css` onto
  `game-play.css` (menu padding / Ollie clearance can shift snapshots).
- Recompressing `public/icons/*.png` (already 3–13 kB; &lt;1 kB expected savings).
- Deleting orphan `public/king.svg` (already excluded from SW precache).
- Narrowing / removing `scheduleIdleGameWarm` (post-paint only; overlaps selector
  idle prefetch — left alone to avoid offline-warm regressions).

## How to re-measure

```bash
npm run build
npm run size:check
PERF_VISUALIZE=1 npm run build   # optional treemap → test-results/perf/stats.html
npm run check:perf               # summary.md + lighthouse; always exit 0
# or bundles only:
PERF_SKIP_LIGHTHOUSE=1 npm run check:perf
```

CI still enforces every `dist/assets/*.js` chunk ≤ 250 kB (raw). Gzip budgets via
`size:check` remain report-only. `check:perf` is **not** wired into CI fail paths.
